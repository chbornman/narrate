Photoproof / tuning registry

Every arbitrary ranking / recommendation factor in one place, so we never lose track of what we decided to weight by how much. Search, retrieval, and the visualization lenses all rest on tunable constants that are otherwise scattered across code, specs, and design docs.

drafted June 13, 2026 - a map, not the source of truth

How to read this. The CODE is the source of truth; this page is the human index that points at it. The consolidated ranking/preview knobs now have ONE home: the typed Tuning config in crates/photoproof-core/src/tuning.rs (the shipped defaults), file-overridable at runtime via tuning.toml in app-data (documented by tuning.default.toml at the repo root) - edit it, restart, re-feel, no rebuild. UI-only knobs live in apps/desktop/src/lib/tuning.ts. Each row gives the current value, where it lives, whether the user can change it (file = override in tuning.toml), and who owns the number - the §12 golden-set retrieval eval (data-driven), the founder (a product judgment), or "fixed" (a budget/contract, deliberately NOT in the editable file so an edit can't silently break an invariant). When you change a default in code, update its row here and tuning.default.toml in lockstep.

Future - the synthesis lens PROPOSED

When the heatmap and the graph both exist, combining them ("hot topics" and the inverse, "missing themes from ignored images") introduces its own weighting - how strongly to weight engagement-inverse against semantic coherence to surface neglected-but-coherent clusters. A knob that does not exist yet; logged so it joins this registry when it does. See the BACKLOG "Visualization lenses" item.

When you add a feature with an arbitrary weight, add its row here. The number you pick today is a guess wearing a default's clothes - this page is how we remember which guesses we made.
