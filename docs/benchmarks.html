Search - visual retrieval (MS-COCO)

The standard image-text retrieval benchmark: real photos, five human-written captions each. Each caption is a query; the right answer is the photo it describes. This honestly tests the CLIP visual + semantic retrieval the app does - exactly what a self-authored note cannot, since a planted note only tests search finding its own injected text.

For 500 real caption queries, CLIP visual search puts the correct photo in the top 10 about 99.6% of the time - near the model's ceiling, as expected from the DFN5B ViT-H encoder. This is the genuine measurement the 7-query journal sketch could not provide.

Full run (1000 photos, ~5000 caption-queries) - completing

The full COCO-1K sweep is embedding on CPU (~20 img/min); this page updates with the larger-sample numbers when it lands. They are expected to track the 100-photo result closely (CLIP is consistent).

Honest scope: COCO photos carry no notes, so this measures PURE VISUAL retrieval (the CLIP S4 signal). The fusion knobs (how much to weight your written notes vs. the visual match) do not move a single-signal ranking, so they cannot be tuned here. Tuning that balance needs a library with REAL notes - and the current dogfood library's notes are test junk, so that benchmark is not yet meaningful. Visual retrieval is benchmarkable today; notes-fusion tuning waits on a real reviewed library.

Voice - transcription (LibriSpeech)

The standard ASR benchmark, built from public-domain audiobooks: 40+ readers, clean per-utterance reference transcripts, a dev split to tune on and a test split to report on. Utterances are joined with a 0.5s silence gap so the endpointer has real boundaries to find. The metric is gating-cost = gated WER minus raw WER, isolating pipeline truncation from the model's own error.

Result - completing

The voice sweep runs after the COCO embed finishes (to avoid model contention on this machine); this section fills with the dev-split gating-cost leaderboard when it lands.

How these are produced

All reusable, committed scripts + binaries (the corpora themselves are gitignored - they hold real data and stay local):

  # search: stage a real photo+caption benchmark, ingest into a throwaway eval
  # library, CLIP-embed, build the golden set, sweep
  scripts/fetch-image-benchmark.sh 1000
  pp-eval-ingest --images .../coco5k/images --lib /tmp/coco-eval-lib \
    --captions .../captions.json --out-golden .../coco-golden.json
  pp-sweep search --db /tmp/coco-eval-lib/photoproof.db \
    --queries .../coco-golden.json --models-dir <models> --json

  # voice: stage a real audiobook benchmark, sweep the endpoint dials
  scripts/fetch-voice-corpus.sh dev-clean
  pp-sweep voice --corpus-manifest .../dev-clean-sweep-subset.tsv \
    --grid "rule2=0.8,1.0,1.2" --model-dir <asr> --server <pp-asr-server> --json

The loop these feed

pp-sweep PROPOSES a better config (you commit it - the machine never auto-changes a setting). make tune-check guards against regressions: it re-runs the cheap synthetic benches and fails if a deterministic quality metric drops (perf is warn-only, since it is machine-variable). Contracts (the <100ms search budget, the timing invariants) stay fixed; only the dials are tuned. See DESIGN-TUNING-LOOP.md.

Photoproof benchmarks - real public data, run on the founder machine. Numbers are measured, not modeled. The saved JSON in docs/benchmarks/ is the reviewable record.
