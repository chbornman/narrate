# Audit: background loops, sync, model downloads, UX, performance (2026-07-07)

Full-codebase audit of the recently landed features and the app's standing
"loops" (ingest pump, reconciliation scans, watcher, preview generation, model
downloads, runtime supervision), plus a UI-performance pass focused on preview
loading at grid scale. Four parallel deep-read audits (feature UX, model
downloads, sync/re-sync machinery, UI performance) plus a test-infra recon.
Every finding below was verified against the code at `b9ff46f`, with file:line
references. Fixes land in follow-up commits that reference the IDs here; when a
fix ships, its row gains a `landed <hash>` note (BACKLOG/LANDED discipline).

Severity: P0 = repo-rule violation / blocker, P1 = major user-facing gap,
P2 = real issue worth fixing soon, P3 = polish / latent.

## 1. Sync / re-sync loops (folders, previews, derived data)

### S1 (P1) No filesystem reconciliation at startup; first scan is the +10 min maintenance tick
`apps/desktop/src-tauri/src/lib.rs:162-201` (setup) runs only
`run_startup_doctor` (`doctor.rs:34`), which reconciles vector spaces and the
preview cache but never calls `scan_root`/`reconcile_all`. The pump seeds
`last_maintenance = Instant::now()` (`pump.rs:278,292-294`), so the first
maintenance reconcile fires ~10 minutes after launch. The `notify` watcher does
not replay events from while the app was closed. Result: deletions show ghost
thumbnails, edits show stale content, and files added while closed are missing
for up to 10 minutes after every launch. `scan.rs:1-2` and `mod.rs:1226-1227`
document "startup" as a canonical reconciliation trigger; it is not wired.
Fix: kick a background `reconcile_all` at launch (natural home: the startup
doctor thread), or seed `last_maintenance` one interval in the past.

### S2 (P1) `on_system_resume` is dead code; sleep/wake never triggers a scan
`crates/photoproof-core/src/library/mod.rs:1247-1252` defines the resume hook
(probe + reconcile) but nothing calls it — no macOS wake observer, no
wall-clock-gap detection. A laptop waking from hours of sleep misses watcher
events silently until the next 10-minute tick. Fix: detect large monotonic/wall
clock gaps between pump iterations and force a reconcile (cross-platform,
no OS observer needed); an OS wake observer can layer on later.

### S3 (P2) `images_version` not bumped on supersede or relink → grid misses in-place edits
The bump lives only in `new_image_tx` (`mod.rs:1629`); `supersede_tx`
(`mod.rs:1776`) and `relink_tx` (`mod.rs:1600`) bypass it. The grid re-lists
only when `imagesVersion` advances (`app.svelte.ts:1009-1012`), so an in-place
edit (content change → supersede) or a live watcher move/relink leaves the grid
stale until an unrelated event. Fix: bump `images_version` on supersede and
relink commits too.

### S4 (P2) Live single-file delete/move never notifies the UI
`observe_removed` (`mod.rs:1496-1522`) marks the path `stale` but bumps no
version and enqueues no pass; `ingest_status` (`pump.rs:168-197`) therefore
never changes and no `ingest-progress` event is emitted. Deleting a file with
the app open leaves a ghost thumbnail until the next folder revisit or scan.
Data stays correct (listing filters `state='active'`); this is purely a
notification gap. Fix: advance `images_version` in `observe_removed` (and the
rename-relink branch) so the seam-1 handshake fires.

### S5 (P2) Preview/vector orphans from deleted images are never reclaimed
`doctor()` (`mod.rs:1363-1374`) only counts `stale_orphans`; thumb/display
artifacts and `.ppvec` rows for images with no active path are kept forever
(only the 1:1 full-decode tier is LRU-evicted, `preview.rs:566`). Unbounded
disk growth for a churning library; contradicts the derived-data-rebuildable
principle's reset/rebuild story. Fix: conservative doctor sweep for images
with no active path older than the move-correlation window.

### S6 (P3) Case-only rename correlation is exact-match; fragile on APFS
`watcher.rs:398-401` correlates renames by exact `rel_path`; on
case-insensitive volumes a case-only rename can leave a duplicate/ghost row.
This is the standing `s02_2` question awaiting a case-sensitivity ruling —
logged here for completeness, not fixed in this pass.

What's good (verified, no churn): running-row crash recovery + idempotent
mark_done, offline-volume claim-skip + retry rescue, model-swap re-embed cohort
gating, clock-shift confirmation sampling, preview temp-file hygiene, the
ingestExpecting watchdog shape, and the seam-1 version handshake on the add
path. The loop set (ingest, sidecar, runtime pumps; watcher; supervisors) has
no silent-stall class bug — the gaps above are notification gaps.

## 2. Model download pipeline

Already strong (verified): pinned repo+revision+sha256+bytes manifest, resumable
`.part` + Range with 200/416 edge handling, SHA-256 verify before atomic rename,
path containment, license gate before byte zero, single-worker dedupe, capture-
aware throttling, graceful quit mid-download, no-"latest" supply chain, TLS via
rustls with no cert bypass. Better than most production downloaders.

### D1 (P1) No disk-space preflight before multi-GB downloads
`runtime.rs:604-679`; Tier-1 consent bundle is ~13.4 GB (`manifest.rs:722`).
No free-space check exists anywhere; a full disk surfaces as a raw Io error
after minutes, with partials left behind. Fix: statvfs-style check of the
models volume before enqueue (required bytes minus already-downloaded, plus
margin); distinct `InsufficientSpace` error; show required-vs-available.

### D2 (P2) Transient HTTP errors (429/5xx) are terminal
Retry loop only re-attempts `DownloadError::Interrupted`
(`runtime.rs:730-732`); an HF CDN 429/503 permanently fails the model until a
manual re-click (`download.rs:400-409,487-492`). Fix: classify 408/425/429/
500/502/503/504 as retryable through the existing backoff (honor Retry-After
when present).

### D3 (P2) No cancel/pause for an in-flight download
No cancellation token exists (`runtime.rs:589-797`); the only way to stop a
13 GB pull is quitting the app. Fix: per-model cancel flag checked in the
chunk loops + a Cancel affordance in Settings → Models.

### D4 (P2) Failed partial downloads are invisible and unreclaimable
Failed models keep `.part` gigabytes under `models_dir/<id>/`; the dir has a
manifest entry so the orphan "reclaim N GB" scan skips it, and the settings row
offers only Download (`SettingsApp.svelte:494-505`, `gc.rs:132-151`). Fix:
surface partial bytes on failed rows with a "Discard partial" action.

### D5 (P3) Progress shows bare percent; no bytes, throughput, or ETA
`SettingsApp.svelte:475-482`; consent card has no live progress at all. The
backend already has cumulative bytes + timestamps. Fix: "1.2 / 3.9 GB · 8 MB/s"
style line in the settings row.

### D6 (P3) Installed models trusted by byte-length only, never re-verified
`download.rs:301-304`; disk corruption surfaces as an opaque spawn failure.
Fix: a doctor/verify action re-hashing a model's files (sha256_file exists).

### D7 (P3) `installed.json` read-modify-write is not lock-guarded
`download.rs:189-221`; single-worker today, but `remove_model` runs on a
command thread. Also `remove_installed_record` lacks the `create_dir_all` its
counterpart has. Fix: serialize mutations; mirror the dir creation.

### D8 (P3) Latent 404: fp16 CLIP manifest entry not hosted
`manifest.rs:536-569` (`revision "local-fp16-convert"`) is offered at tiers 1-2
but the artifact is dev-staged only; an unstaged machine configured for it
would download-fail forever. Fix: stop offering it at any tier until hosted
(the Nemotron staging pattern), or host + pin a real revision.

## 3. Recently landed features (UX)

### U1 (P1) Diversify silently hides newly-ingested images during an active ingest
Mid-ingest re-lists (`app.svelte.ts:935-972,1012-1022`) call `grid.setItems()`
without re-running the diversify pass, and `filterToShown`
(`grid.svelte.ts:104`) drops any hash not in the stale `diversifyShown` set.
Import-and-review with Diversify on hides every new photo with no hint (the
"N hidden" count doesn't grow either). Fix: after a mid-ingest re-list that
changed scope hashes, invalidate `diversifyScopeKey` and re-run the pass.

### U2 (P2) `selectRedundantDuplicates` mis-focuses and skips scope reporting
`app.svelte.ts:3130-3139` sets `focus: 0` — an index into the *unit list*, not
the gathered hashes — so the inspector/rating/Look target is generally an
unselected keep-worthy image; and it bypasses `reportScope()`, so the backend
write scope and the "● N" indicator lag. Fix: focus/anchor =
`unitHashes.indexOf(hashes[0])` (or -1), then `await reportScope()`.

### U3 (P2) Seam-2 force-reembed is unreachable from the UI
`force_reembed` is registered (`lib.rs:295,394`, `commands/app.rs:322`) but has
no TS binding and no caller. Fix: wire a deliberate affordance (Settings →
Models) or an explicit dev-console-only note.

### U4 (P3) Toggling a lens on triggers a redundant second backend pass
`toggleDiversify`/`toggleDuplicates` (`app.svelte.ts:2947-2959,3068-3079`)
blank the scope key and fetch, but the fetches never record the scanned key, so
the next `reportScope` re-runs the same (O(n²) for dedup) pass. Fix: record the
scope key in the fetch paths.

### U5 (P3) `DuplicatesView` never cancels its slider debounce on unmount
`DuplicatesView.svelte:53-61`; the `dedup.ts:159-178` contract says `cancel()`
on unmount. Guarded so harmless today. Fix: `onDestroy(() => sweep.cancel())`.

### U6 (P3) Diversify has no in-flight indication (Duplicates lens has one)
`GridHeader.svelte:308-333`: stale shown set + stale "N hidden" with no pending
hint while the pass runs. Fix: quiet pending affordance on the count.

### U7 (P3) Diversify/heat scope signatures omit `gridScope.kind`; dedup includes it
`app.svelte.ts:2997,723` vs `:711`. Same-size same-endpoint scopes of different
kinds fail to re-run. Fix: prefix `gridScope.kind` in all three.

### U8 (P3, log only) Duplicates lens thumbs bypass the Thumb retry path and are non-interactive
`DuplicatesView.svelte:120-140`. Display-only is stated v1 scope; logged for
the Tier-1 follow-up.

What's good: monotone async-token discipline on every new lens, backend scope
hardening (`enumerate_scope` intersects against live active set), honest
degraded states, the topic-by-phrase fix, the watchdog lifecycle, graph cache
keying on vectorsVersion, and the seam-1 handshake replacing the poll.

## 4. UI performance (preview loading at scale)

Already good (verified): real windowed virtualization with `<img>` recycling
(`gridlayout.ts:77-104`, `Grid.svelte:58-64`), custom `photoproof://` protocol
with immutable cache headers (no base64-over-IPC), `decoding="async"` + CSS-only
shimmer, stale-pixel guards on recycled imgs, `previewReady` gating (no 404
storms), viewport-first server-side preview prioritization, single-statement
grid query on `spawn_blocking`, debounced version-handshake re-lists, and a
bounded-concurrency viewport-priority thumb queue in the graph lens.

### F1 (P1) Protocol handler spawns an unbounded OS thread per request
`lib.rs:144`: every `photoproof://` request gets a fresh `std::thread::spawn`
doing blocking I/O; fling-scrolls burst dozens-to-hundreds of transient
threads competing for FS and `db.lock()`. Fix: bounded worker pool (e.g.
`tauri::async_runtime::spawn_blocking` or a small dedicated pool).

### F2 (P2) O(selection) membership test per cell per scroll frame
`Grid.svelte:335` → `selection.ts:29-31` (`order.includes(hash)`). Select-All
on 10k then scroll ≈ 1.5M string compares per frame. Fix: Set-backed
membership alongside `order`.

### F3 (P2) Grid always decodes the 512px thumb tier, even into 96px cells
`Thumb.svelte:18,155` always `thumbUrl` (512px); `microUrl` (96px) exists
(`urls.ts:22`, `preview.rs:47`) but only the graph uses it. Zoomed-out grids
hold ~28x the needed decoded pixels (~150 MB vs ~5 MB for the mounted window).
Fix: pick tier by display size (micro for thumbSteps ≤160px); the existing
previews-changed heal path covers 404-until-regen.

### F4 (P2) No client-side load ordering/cancellation on fling
`Thumb.svelte:248-253` `loading="eager"` for the whole overscan; superseded
requests keep completing. The graph's `ThumbQueue` pattern
(`thumbqueue.ts`) solves this. Fix (medium, optional): reuse it for the grid
or demote overscan rows to `fetchpriority="low"` until scroll-settle.

### F5 (P3) Full-array deriveds recompute on every mid-scan re-list
`grid.svelte.ts:105-125`: sort + 3 maps + `stacks.buildUnits` re-run per
re-list on 10-20k folders. Bounded, off the render path. Baseline via the perf
tests; optimize only if measured hot.

### F6 (P3) Two correlated EXISTS subqueries per grid row
`library/mod.rs:2996-3005`: ~40k subquery executions per 20k-folder list,
repeated per mid-scan re-list. Verify covering indexes; consider LEFT JOIN
rewrite only after the grid-list bench exists.

### F7 (P3) Full-res protocol routes read whole files, no ranges
`protocol.rs:133,165`. Fine for thumbs; Look-scale only. Future item.

## 5. Perf-test plan (preview loading at hundreds/thousands of assets)

There is currently zero automated perf coverage for preview serving or grid
behavior. Plan, matching existing idioms (`search_latency.rs` for #[ignore]
release budget tests; `pp_bench` + `bench-results.jsonl` for scenarios;
vitest for logic budgets):

- **T1 (Rust)** `apps/desktop/src-tauri/tests/preview_serve_latency.rs`:
  temp Library with 1k/5k generated thumb artifacts; p50/p99 serve budgets
  cold/warm; a 200-way concurrency case that locks in the bounded-pool fix
  (F1) and fails if unbounded spawn returns.
- **T2 (bench)** `pp_bench` scenarios `preview-serve` and `grid-list`
  (list_folder latency at 1k/5k/20k) appended to `bench-results.jsonl`;
  wire into `tune-check` baselines.
- **T3 (vitest)** windowing invariant at 1k/10k/50k items (`slots` bounded
  by viewport, render-everything tripwire); selection membership budget with
  Select-All 10k (guards F2); derived-recompute budget on `setItems(10k)`
  (baselines F5).
- **T4 (optional, later)** headless scripted-scroll harness counting protocol
  requests fired vs cells settled.
